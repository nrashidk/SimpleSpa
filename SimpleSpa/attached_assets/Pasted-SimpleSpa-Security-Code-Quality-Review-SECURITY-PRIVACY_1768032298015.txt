SimpleSpa Security & Code Quality Review
🔴 SECURITY & PRIVACY - CRITICAL ISSUES
1. Multi-Tenancy Isolation Failure (CRITICAL)
Risk Level: HIGH - Data Breach Potential

Issue: Many admin routes lack spa-level isolation checks. Admins can potentially access/modify data from other spas.

Affected Endpoints (50+ routes):

GET/POST/PUT/DELETE /api/admin/products - No spa isolation check
GET/POST/PUT/DELETE /api/admin/customers - Missing spaId validation
/api/admin/bookings, /api/admin/invoices, /api/admin/staff - Similar issues
Example Vulnerability (server/routes.ts:2750-2758):

app.get("/api/admin/products", isAdmin, async (req, res) => {
  const products = await storage.getAllProducts();  // ❌ Returns ALL products from ALL spas
  res.json(products);
});

Exploitation: Admin from Spa A can view/modify products, customers, invoices from Spa B by manipulating API requests.

Remediation:

IMMEDIATE: Add injectAdminSpa middleware to ALL /api/admin/* routes
Filter all queries by spaId from req.adminSpa.id
Add ownership validation before any UPDATE/DELETE operations
// Correct implementation
app.get("/api/admin/products", isAdmin, injectAdminSpa, async (req: any, res) => {
  const products = await storage.getProductsBySpaId(req.adminSpa.id);
  res.json(products);
});

2. Development Endpoints in Production (CRITICAL)
Risk Level: HIGH - Complete System Compromise

Vulnerable Endpoints (server/routes.ts:361-446):

POST /api/dev/make-super-admin        // Line 362 - No authentication
POST /api/dev/create-super-admin      // Line 387 - No authentication

Exploitation: Any unauthenticated user can create super admin accounts with full platform access.

  -H "Content-Type: application/json" \

3. Missing CSRF Protection (HIGH)
Risk Level: HIGH - Account Takeover

Issue: No CSRF tokens on state-changing operations. Cookie-based sessions are vulnerable to CSRF attacks.

Affected: All POST/PUT/DELETE endpoints

Exploitation:

<!-- Malicious website -->
<form action="https://victim-spa.com/api/admin/services/1" method="POST">
  <input name="price" value="0.01">
</form>
<script>document.forms[0].submit();</script>

Remediation:

Implement CSRF token middleware (use csurf package)
Validate Origin/Referer headers
Consider SameSite cookie attribute (already set to secure: true but missing sameSite)
// server/replitAuth.ts:40
cookie: {
  httpOnly: true,
  secure: true,
  sameSite: 'strict',  // ADD THIS
  maxAge: sessionTtl,
}

4. Weak OAuth State Validation (HIGH)
Risk Level: HIGH - OAuth Hijacking

Issue (server/routes.ts:595-602):

const stateData = JSON.parse(Buffer.from(state as string, 'base64').toString());
const { spaId, integrationType, userId, timestamp } = stateData;

// Verify state is recent (within 10 minutes)
if (Date.now() - timestamp > 10 * 60 * 1000) {
  return res.redirect('/admin/settings?oauth_error=expired_state');
}

Vulnerabilities:

❌ No cryptographic signature - state can be forged
❌ No server-side storage - replay attacks possible
❌ No userId verification - attacker can hijack another user's OAuth flow
Exploitation: Attacker creates OAuth state for victim's userId, victim approves OAuth, attacker gets access tokens.

Remediation:

Use cryptographically signed state (HMAC with secret key)
Store state server-side in Redis/database with TTL
Verify req.user.claims.sub === stateData.userId
5. Insecure File Upload (MEDIUM-HIGH)
Risk Level: MEDIUM - Path Traversal, File Execution

Issue (server/routes.ts:157-170):

app.post('/api/upload/license', upload.single('file'), (req, res) => {
  if (!req.file) {
    return res.status(400).json({ message: 'No file uploaded' });
  }
  const fileUrl = `/uploads/licenses/${req.file.filename}`;
  res.json({ fileUrl });
});

Vulnerabilities:

❌ No authentication - anyone can upload files
❌ Only file extension validation (easily bypassed with double extensions like malicious.pdf.php)
❌ Files served from same domain (potential XSS via HTML/SVG uploads)
Remediation:

IMMEDIATE: Add authentication middleware
Validate file content (magic bytes), not just extension
Store files on separate domain/CDN to prevent cookie theft
Scan uploads with antivirus
app.post('/api/upload/license', isAuthenticated, upload.single('file'), async (req, res) => {
  // Validate magic bytes
  const fileBuffer = fs.readFileSync(req.file.path);
  const fileType = await import('file-type').then(m => m.fileTypeFromBuffer(fileBuffer));
  
  if (!['application/pdf', 'image/jpeg', 'image/png'].includes(fileType?.mime)) {
    fs.unlinkSync(req.file.path);
    return res.status(400).json({ message: 'Invalid file type' });
  }
  // ...
});

2. Missing Database Transactions
Issue: Multi-step operations not wrapped in transactions.

Example (server/routes.ts:1454-1520):

app.post("/api/super-admin/applications/:id/approve", async (req, res) => {
  // 1. Create spa
  spa = await storage.createSpa({...});
  
  // 2. Update user (separate DB call)
  await storage.upsertUser({...});
  
  // 3. Update application (separate DB call)
  await storage.updateAdminApplication(id, {...});
  
  // ❌ If step 3 fails, spa and user are created but application still pending
});

Impact: Inconsistent state, orphaned records.

Remediation:

await withTransaction(async (tx) => {
  const spa = await tx.createSpa({...});
  await tx.upsertUser({...});
  await tx.updateAdminApplication(id, {...});
});

3. N+1 Query Problem
Issue: Multiple endpoints fetch related data in loops.

Example (server/routes.ts:1419-1446):

const enrichedApplications = await Promise.all(
  applications.map(async (app) => {
    const user = await storage.getUser(app.userId);  // N queries
    const reviewer = app.reviewedBy ? await storage.getUser(app.reviewedBy) : null;  // N more queries
    return { ...app, user, reviewer };
  })
);

Impact: Severe performance degradation with scale.

Remediation: Implement JOIN queries or batch loading:

async getAllAdminApplicationsWithUsers() {
  return db.select()
    .from(adminApplications)
    .leftJoin(users, eq(adminApplications.userId, users.id))
    .leftJoin(reviewers, eq(adminApplications.reviewedBy, reviewers.id));
}
