Executive Summary
SimpleSpa is a production-grade, multi-tenant SPA/Salon management platform with comprehensive features including booking, payments, inventory, finance, and WhatsApp integration. The codebase demonstrates strong security fundamentals with proper CSRF protection, rate limiting, encryption, and audit logging. However, there are critical vulnerabilities and architectural issues that require immediate attention.

Overall Security Posture: 7/10 (Good foundation, critical gaps)
Code Quality: 6.5/10 (Working but needs refactoring)
Product Viability: 8/10 (Feature-complete but scalability concerns)

1. SECURITY & PRIVACY (Critical Issues Only)
🔴 CRITICAL: In-Memory OTP Storage (Data Loss Risk)
Location: server/firebaseAuth.ts:331

const otpStore = new Map<string, { otp: string; expiresAt: number; attempts: number }>();

Issue: OTPs are stored in process memory and lost on server restart, leaving users unable to log in mid-flow.

Risk:

High availability impact: Service restart = broken authentication
Multi-instance failure: Won't work with horizontal scaling (each instance has separate memory)
Security: No cleanup mechanism = memory leak potential
Remediation:

// Option 1: Store in PostgreSQL with TTL-based cleanup
// Add table: otp_codes (phone, otp_hash, expires_at, attempts)
// Index on expires_at for efficient cleanup

// Option 2: Use Redis with automatic expiration
await redis.setex(`otp:${phone}`, 600, JSON.stringify({ otp: hashedOTP, attempts: 0 }));

Priority: P0 (Blocks production scaling)

🔴 CRITICAL: Stripe Webhook Without Signature Verification
Location: server/stripeWebhook.ts:16-21

if (webhookSecret) {
  event = stripe.webhooks.constructEvent(payload, signature, webhookSecret);
} else {
  logger.warn('[Stripe Webhook] No webhook secret configured, parsing payload directly');
  event = JSON.parse(payload.toString());  // 🚨 DANGEROUS
}

Issue: If STRIPE_WEBHOOK_SECRET is not set, any attacker can forge payment confirmations by sending crafted webhook requests.

Attack Scenario:

Attacker creates booking
Sends forged checkout.session.completed event
Booking marked as "Paid" without actual payment
Attacker gets free service
Remediation:

// REQUIRED: Fail fast if secret not configured
const webhookSecret = process.env.STRIPE_WEBHOOK_SECRET;
if (!webhookSecret) {
  logger.error('[Stripe Webhook] STRIPE_WEBHOOK_SECRET not configured - rejecting webhook');
  return { success: false, error: 'Webhook verification not configured' };
}
event = stripe.webhooks.constructEvent(payload, signature, webhookSecret);

Priority: P0 (Enables payment fraud)

🟠 HIGH: Potential IDOR in Multi-Tenant Isolation
Location: server/routes.ts - Multiple endpoints

Issue: While most admin endpoints use injectAdminSpa middleware to enforce tenant isolation, there are inconsistencies that could allow cross-tenant data access.

Example (routes.ts:2607):

app.get("/api/admin/memberships/:id", isAdmin, async (req, res) => {
  // ⚠️ Missing injectAdminSpa - doesn't verify membership belongs to admin's spa
  const membership = await storage.getMembership(parseInt(req.params.id));
  // Admin from Spa A could read Spa B's memberships
})

Remediation Pattern:

// ALWAYS verify spaId ownership for GET/:id, PUT/:id, DELETE/:id
app.get("/api/admin/memberships/:id", isAdmin, injectAdminSpa, async (req: any, res) => {
  const membership = await storage.getMembership(parseInt(req.params.id));
  
  // Critical: Verify tenant ownership
  if (!membership || membership.spaId !== req.adminSpa.id) {
    return res.status(404).json({ message: "Membership not found" });
  }
  
  res.json(membership);
});

Audit Required: Review ALL 200+ routes for missing tenant checks, especially:

GET /api/admin/:entity/:id
PUT /api/admin/:entity/:id
DELETE /api/admin/:entity/:id
Customer data endpoints (bookings, invoices, profiles)
Priority: P1 (Data breach risk)

  if (req.dbUser.role !== 'super_admin' && file.spaId !== req.dbUser.adminSpaId) {
    return res.status(404).json({ message: 'File not found' });
  }

Issue: Multi-step operations not wrapped in transactions

Example Risk:

Remediation:

  await storage.createMembershipUsage(usageData, tx);
});
